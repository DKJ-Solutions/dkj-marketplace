# Release notes v7.8.0 🚀

**Date:** 2026-11-27\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

Most repos need do nothing beyond updating. If you run the CI floor, your session start may now
report a runner or gate caller as `[BEHIND]`: re-run the adopt skill it names. Eight one-time skills
are now typed as slash commands. After that come self-maintained references, a way to measure them,
and a round of fixes.

### Steps worth taking

- **Re-place a runner that is reported `[BEHIND]`.** Your session start now compares the CI-floor
  runners (`fold-on-merge.yml`, `merge-on-green.yml` and the rest) and the two gate callers
  (`branch-entry.yml`, `always-on-budget.yml`) with what this version would place. Where one is behind,
  it prints the first differing line. Run `adopt-ci-floor` or `adopt-dkj-repo-workflow` again to take
  the new copy. No `[BEHIND]` line means no action.
- **With a hotfix lane, check your live branch's caller.** Your session start now also reads the copy
  of `branch-entry.yml` on your live deploy branch. A `[WARN]` there means hotfix PRs to `live` are not
  gated yet; merge the trunk's caller into `live` as the warning says.
- **Type the one-time skills yourself.** The adopt skills, `scheduled-tasks`, the two stopwatch
  skills, `record-suite-durations` and `dependabot-entry` no longer start on their own. Start them by
  typing, for example `/adopt-dkj-repo-workflow`.

### New for every team

- **Skills trigger again.** Every skill a session can start on its own has a short description, so
  skills such as `asana-intake`, `day-plan` and `tidy-machine` are no longer listed name-only and
  fire when you ask for them.
- **See your skill budget.** `measure-skill` reports how many characters your enabled plugins' skill
  descriptions spend on Claude Code's listing, and names any description long enough to be dropped.
- **Specialists keep their own references.** A specialist with a canon page writes each useful web
  source into your repo's source store in the same task, so the next search starts from it.
- **Measure whether that saves searches.** Specialists end a research deliverable with one
  `References:` line. Run `/measure-references` for the counts per specialist and per week.
- **Hotfix PRs are checked before they open.** A `gh pr create` to your live branch is refused while
  the branch's changelog entry is unwritten. Repos without a live branch see no change.

### New for life hubs

- **Collections are rows, not dossiers.** Ian files a track, a film or a trip as a row in a
  collection database for that kind, and no longer sends what you watched or did to the taste dossier.

### Fixes you will notice

- **One bad entry no longer blocks the fold.** A malformed changelog entry is set aside and named,
  and the valid entries beside it are folded, so a release no longer misses them.
- **Closing issues in a loop asks first.** In a BWJ store, a `gh issue close` on an issue number from
  a variable now raises a permission prompt. Close one literal number per command so each Asana task
  gets its go-live block.
