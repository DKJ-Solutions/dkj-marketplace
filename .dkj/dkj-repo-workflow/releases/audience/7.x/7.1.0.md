# Release notes v7.1.0 🚀

**Date:** 2026-11-18\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

**No action is required to take this update.** Run `update-plugins` (or
`claude plugin marketplace update dkj-marketplace` first, then update). Two changes below can refuse
something that used to pass. Each one names its one-line repair when it does.

### Trunk commits are refused

A session that runs `git commit` while it is on the trunk is now stopped and pointed at `new-branch`. Only
the workflow's own bounded commits pass (`fold:`, `release:`, `release-prep:`, `release-notes:`). Before,
"never directly on the trunk" was a rule in prose only, so such a commit landed and failed at push time,
or not at all. If the guard cannot tell which branch you are on, it lets the commit through (#4286).

### Line-ending mismatches stop at open-pr

On Windows, `open-pr` now refuses a branch with a CRLF file where `.gitattributes` pins `eol=lf`, and prints
the repair: `git add --renormalize -- <paths>`. You no longer meet that mismatch later, as an unexplained
modification when `ship-pr` returns to the trunk. A repo that kept its own EOL check can drop it (#4288).

### Migration steps run in order

If you have not migrated to 7.0.0 yet, the steps in the 7.0.0 note now work in the order given:

- Part 1 of `adopt-dkj-repo-workflow` moves the old folder even when your migration branch's document
  already sits in the new one. You no longer move the document aside by hand (#4251).
- Part 1 repoints every old folder path, including a `.gitignore` exception line and every path in the
  PR template (#4255).
- `adopt-ci-floor` prints which workflows wake the merge-on-green sweep, and warns when one is missing
  (#4258).
- The 7.0.0 note itself now lists every step, including re-vendoring the brand book from the same tag you
  pin its gate to (#4253, #4256).

**Did your progress bar go dark after 7.0.0?** Re-run `adopt-statusline.ps1 -Apply`. It now replaces the
stale shim it placed itself (#4252).

### CI runners pin your release

A repo adopting the workflow now gets CI runners pinned to the release it adopted, and so does the
brand-book gate the `dkj-brandbook` skill hands you. A script that moves on the source's `main` no longer
turns your checks red before a release carries it (#4237, #4246). A repo adopted earlier keeps its `@main`
callers and works as before. Re-running `adopt-workflow-folder` or `adopt-ci-floor` names the line to
change if you want to pin them.

### Sweeps skip parked issues again

`issues-sweep` no longer offers parked issues as free. In 7.0.0 every parked issue read `free`, and a
cleared wait never showed as `stale-park` (#4248). The build step of a sweep now runs in a fresh subagent
on a cheaper model, while the choices stay in your session (#4240).

### New in dkj-repo-workflow

- **dependabot-entry** writes the development document onto a Dependabot PR's branch, so the bump passes
  the branch-entry gate. It leaves the three questions a bump owes for a person to answer (#4287).
- **A plugin-script forwarder.** Replace your own `scripts/lib/plugin-scripts.ps1` with
  `templates/plugin-scripts-forwarder.ps1`, and the next plugin rename reaches you as an update instead of
  a code change. Every `Resolve-PluginScript` call keeps working (#4259).

### Brand book

- A page that still reads `--text-lg`, retired on November 1, now gets a `[retired]` finding. Before, its
  text quietly fell back to the inherited size. Use `--text-h3` (#4254).
- A session start in a repo with the brand book is several seconds faster: its check now takes under a
  second on a warm start (#4234).

### New Shopify store skills

Six checks that one store kept as its own scripts now ship in `dkj-subagents-shopify`, so every store gets
them with an update:

- **which-theme** tells you which theme a storefront URL actually serves (#4289).
- **sync-summary** turns a live-drift sync into a short report of what changed per theme area. A store
  whose sync commits do not start with "sync" answers `Get-ShopifySyncReferencePattern` (#4289).
- **live-direct-writes** opens an issue when someone pushes to a Git-connected live theme past the branch
  flow. Re-run `adopt-shopify-floor` to place it (#4289).
- **check-jsonld** validates structured data per market, also on a preview theme (#4290).
- **check-sitemap** reports duplicates and, with `-Catalog`, pages missing from the sitemap. Accented
  handles are no longer reported as missing (#4290).
- **measure-buybox** measures where the add-to-cart button sits at a real mobile width, and prints PASS or
  FAIL against your expectation in `Get-ShopifyBuyBox`. It needs Node 22.7 or newer (#4290).

The market-aware checks read your markets from `Get-StorefrontMarkets`.

### BWJ stores

- **start-task** and **move-asana-task** now ship in `dkj-repo-workflow-bwj`, so a fix reaches both stores
  with one release (#4271, #4291).
- Asana cards on two boards now move on your own board when their issue closes, instead of staying put
  (#4282).
- An issue closed without a go-live block is labelled `result-owed`, and every session names it until the
  result message is written. Re-copy the `asana-closed-message` template to take this; it needs
  `issues: write` (#4267).
- Filing an inbound issue with `-R $R`, or with a heredoc body that quotes a command, is no longer refused
  (#4293).

### Life hub

- Ian, Onyx, Astrid, Fiona and Hugo can work with a knowledge base behind a connector such as Notion
  again, as subagents (#4277).
- `/agenda` turns an action you accept into a card in your Tasks database, without duplicates. Name the
  database and its relation on your settings page to switch it on (#4279).

### Cloud sessions can file issues

A Claude Code cloud session where `gh issue create` is unavailable now files through the REST API instead
of concluding there is no tracker (#4278).
