# Release notes v7.2.0 🚀

**Date:** 2026-11-19\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

No action is required for this update. Four items below let you delete something your repo kept as a
workaround. Each one says what you can delete, and keeping it breaks nothing.

### Optional cleanups you can make

- **You can drop your own published-page check.** A BWJ store's `publish-page.ps1` now fetches the public
  URL of every page it publishes and exits 0 only when that URL serves exactly the uploaded bytes. It
  retries for up to a minute. If you wrapped the publish in a script that fetched the link by hand, you
  can delete it. `-NoVerifyServed` turns the check off.
- **You can drop the lint forwarder.** `Get-LintScript` may now return a rooted path, so a store can
  point its lint gate straight at the plugin's `lint-brain.ps1` through `Resolve-PluginScript`. The
  `dkj-repo-workflow-bwj` README shows the three lines that replace the forwarder. A repo-relative answer
  works as before.
- **You can drop a local branch-reminder hook.** Every prompt made while you are on the trunk now gets
  a one-line notice that names the skill that opens a branch (`new-branch`, or `start-task` where the BWJ
  extension is enabled). If you built this notice yourself, you can remove your hook.
- **You can drop your forwarder equality test.** A new session check tells you at session start when
  `scripts/lib/plugin-scripts.ps1` differs from the template the installed plugin ships, and gives the
  one-line fix. Line endings and a BOM do not count as a difference.

### Fixes you will notice

- **The lint gate passes on correct release history again.** A BWJ store's `lint-brain` no longer
  fails on its own frozen release records under `.dkj/`. It also no longer flags a mojibake sequence
  quoted inside an inline code span, so you no longer have to delete a documented repair to get the gate
  green. You no longer need `-SkipLint` for either case.
- **A ship no longer fails on a cancelled CI run.** When a PR got a second CI run on the same commit,
  `ship-pr` could end with "NOT merged, NOT folded" on a branch that was fine. It now waits for the run
  that replaced the cancelled one and merges on that result.

### New

- **Move app data out of git into OneDrive.** The developers team has a new skill,
  `move-data-to-onedrive`. It moves editable data your repo keeps in git into
  `%OneDrive%\<org>\<repo>\<data-name>\`, in six measured steps. The steps also cover the two traps that
  caught the first move: `.env.local` separating the dev server from the scripts, and a test overwriting
  the real OneDrive data.
