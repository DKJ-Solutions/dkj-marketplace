# Release notes v7.0.0 🚀

**Date:** 2026-11-17\
**Type:** Major\
**For whom:** consumers of this product

The workflow plugin becomes dkj-repo-workflow, the developers team splits off the core team, and issues-sweep loads only the step in hand

## What changed

**This is a major: every repo has to act once, on a branch, before it takes this update.** Two plugins
were renamed and one was split, so the names in your `.claude/settings.json` stop resolving. The steps are
below, most urgent first; everything else arrives with the plugin update (`update-plugins`).

### You must: move to the new plugin names

The workflow plugin `dkj-policy` is now `dkj-repo-workflow`, `dkj-solutions` is `dkj-repo-workflow-dkj`
and `bwj-development` is `dkj-repo-workflow-bwj`. The workflow folder `.dkj/dkj-policy/` is now
`.dkj/dkj-repo-workflow/`, and the shared scripts read only the new folder. Until you move, a session in
your repo runs without the workflow plugin at all.

0. Refresh the marketplace clone first: `claude plugin marketplace update dkj-marketplace`. A clone
   that predates this release does not hold v7.0.0, and every step below assumes it does.
1. In `.claude/settings.json`, replace each `enabledPlugins` key: `dkj-policy@dkj-marketplace` becomes
   `dkj-repo-workflow@dkj-marketplace`, `dkj-solutions@...` becomes `dkj-repo-workflow-dkj@...`, and
   `bwj-development@...` becomes `dkj-repo-workflow-bwj@...`. Then run
   `claude plugin install <id> --scope project` for each. `plugin-versions` and `update-plugins` name
   every old id with this repair. In the same file, rewrite every `permissions.allow` pattern naming
   `dkj-policy` (such as `*dkj-policy*new-branch.ps1*`) to `dkj-repo-workflow`: the old patterns match
   nothing any more, so every shared-script call starts asking for permission again.
2. Run Part 1 of `adopt-dkj-repo-workflow` with `-Apply`. It moves the folder in one `git mv` and
   repoints `scripts/repo-config.ps1`, `.gitignore`, the PR template and the `CLAUDE.md` imports.
   Until it runs, the session check names the old folder as an `[ERROR]`. **At v7.0.0 Part 1 refuses
   once `new-branch` has created `.dkj/dkj-repo-workflow/`, which step 1's branch does** (#4251): move
   the branch document out of the tree, remove the empty folder, run Part 1 with `-Apply`, and put the
   document back. The next release moves the folder beside it.
3. Repoint every CI runner, not only two. `fold-on-merge.yml`, `merge-on-green.yml`,
   `verify-resolved.yml` and `repo-settings.yml` run `plugins/dkj-policy/scripts/...` out of a checkout
   of this repo, and `repo-settings.yml` checks out `ref: main`, so it is red already. Part 1 also
   prints a `[pin]` line for each of `branch-entry.yml`, `always-on-budget.yml` and `house-style.yml`
   that still calls `@main`. **A repo that vendors the brand book re-vendors `house-style.css` and
   `house-product.css` from the same tag in the same change** (#4256): the gate holds the vendored copies to
   that tag's checksums, so moving `house-style.yml` alone turns it red, although at v7.0.0 the two files
   differ from 6.x only in comments. The clean repair is to delete the runners `adopt-ci-floor` placed and
   re-run it with `-Apply`: in the first repo migrated, nothing repo-specific was lost. **Run Part 1
   before it** when you delete `branch-entry.yml` and `always-on-budget.yml` too: `merge-on-green.yml`
   wakes on the pull-request workflows present when `adopt-ci-floor` runs, so without them it drops both
   from its list (#4258).
4. Re-adopt `Get-MojibakePaths` in `scripts/repo-config.ps1` from the blueprint (Part 2). Its folder
   names are written without quotes around a path, so Part 1's repoint does not reach them, and the
   mojibake check silently stops covering the moved folder.
5. Search your own scripts for the old ids, not only `settings.json`. A repo-local helper that resolves
   plugin scripts by id and still defaults to `dkj-policy` finds the disabled 6.x install record and runs
   6.x code without an error.
6. Re-run `adopt-statusline.ps1 -Apply` after the next release, or delete
   `.claude/statusline/dkj-progress.ps1` and re-run it now: a shim placed before this release looks for
   `dkj-policy` and the progress bar goes dark (#4252).
7. A BWJ store repo may also move `.dkj/bwj-development/` to `.dkj/dkj-repo-workflow-bwj/`, as
   `adopt-dkj-repo-workflow-bwj` describes. That step is optional.

`claude plugin list` keeps a disabled `dkj-policy@dkj-marketplace 6.x` record for each migrated repo.
Leave it while other repos on this machine are still on 6.x, and uninstall it at project scope once none
are.

### You must: enable the developers team

The core team is now two plugins. `dkj-subagents-alpha` keeps the specialists who work anywhere, and is
what the Claude App gets. The ten whose craft needs a repository (Derek, Rendall, Sylvester, Cody, Tycho,
Victor, Sebastian, Ravi, Nolan, Tessa) and the skills `specialists-init`, `specialists-teardown` and
`sync-roster` moved to `dkj-subagents-developers`. Without it a session has eleven specialists instead of
twenty-one, and the new session check says so with the line to add.

Add `"dkj-subagents-developers@dkj-marketplace": true` beside the core team, run
`claude plugin install dkj-subagents-developers@dkj-marketplace --scope project`, and restart. Then run
`claude plugin update dkj-subagents-alpha@dkj-marketplace --scope project`: an install says "already
installed" and leaves the core team on 6.x. Roster rows need no change, but **two lenses do**: the
opening blockquote of `specialist-05-05-lens.md` (Derek) and `specialist-05-06-lens.md` (Rendall) names
the body under `dkj-subagents-alpha/personas/`, and both bodies moved to
`dkj-subagents-developers/personas/`. `sync-roster` never rewrites a lens that exists, so correct that
path by hand. The new session check then reports the repo as `[UNLISTED]` in the consumer register,
which lives in the marketplace repo: its maintainers add the plugin there, not your migration PR.
The slash commands are now `/dkj-subagents-developers:specialists-init`,
`/dkj-subagents-developers:sync-roster` and `/dkj-subagents-developers:specialists-teardown`.

### Sweeps: cheaper, and fairer to more than one developer

- `issues-sweep` loads a 13.7 KB loop page instead of a 35 KB one, and that page stays in context for
  every turn of a sweep. What applies to one case only (a refused claim, a lane, a park) sits on a page
  beside it, read when that case comes up.
- You can park a decision, a look or an act on the developer it belongs to:
  `claim-issue -Park <label> -Decider <login>`. `issues-sweep-decisions` and `issues-sweep-reviews` then
  put it only to that account. Without `-Decider` nothing changes.
- An issue waiting on another repo's pull request that has merged but not been released now reads as
  `relabel`, with the one line that moves it to `awaiting-release-external`.

### A repo can drop the changelog

If nobody reads your changelog, add `function Get-ChangelogMode { 'none' }` to `scripts/repo-config.ps1`.
A branch then carries only its work commits: no `park:` or `fold:` commits, and the PR body becomes the
record. The trade-off: work reaches `origin` only when `open-pr` pushes it. `prune-merged` cleans up the
local branch documents such a repo leaves behind. Every other repo keeps the full route unchanged.

### Session checks that catch more

- A BWJ store session starts with an `[ERROR]` naming every open issue without exactly one kind label,
  or with the reach label but no `## Why <reach label>` section, each with its repair.
- Every issue a session files on a BWJ store repo carries a hidden stamp of the plugin versions it ran,
  so `gh search issues filed-with` answers *which version filed this?*
- The consumer register no longer reports runners pinned to a release as broken when only `main` has
  moved, so it no longer suggests a repair that would break them.

### Smaller things

- A life hub gets `/dkj-subagents-lifehub:agenda-sync`: Google Calendar into the Notion Agenda every
  day, also as a cloud routine that runs without your PC on.
- Old brand-book addresses and bookmarks land on the brand book again instead of a 404.
