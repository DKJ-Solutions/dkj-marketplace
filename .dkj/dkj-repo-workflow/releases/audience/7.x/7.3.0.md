# Release notes v7.3.0 🚀

**Date:** 2026-11-20\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

A BWJ store has one action to take after this update, and it comes first below. Every other repo needs
no action. The rest makes sweeps, issue handling and session starts do more of the work for you.

### Action for BWJ stores

- **Move your Asana workflows onto the pinned scripts, once.** The three Asana workflows
  (`asana-closed-message`, `asana-prio-label`, `asana-open-section`) now run their script from a pinned
  checkout of the marketplace instead of a copy in your `.github/scripts/`. Run step 1 of
  `adopt-dkj-repo-workflow-bwj`. It replaces the workflows and removes the copies. Until you do, your
  session start names each copy left behind. After that, a fix to these workflows reaches you by moving
  one `ref:` line.

### New

- **See your own open issues at session start.** Every session now tells you how many open issues your
  account filed in the repo, with the one command that sweeps only those. It stays silent when you have
  none.
- **Sweep only your own issues.** In a repo two people share, `claim-issue.ps1 -Candidates -Author @me`
  and `issues-sweep-decisions --author @me` skip everything your sessions did not file.
- **A sweep no longer waits out CI after each issue.** `ship-pr -HandOff` leaves the pull request armed
  to merge on green and the sweep goes on to the next issue. If one of those pull requests later goes red
  or gets stuck, your next session start and the next sweep name it, with the commands to resume it.
- **Take over a colleague's issue in one command.** Once they agree, `claim-issue <n> -ApprovedBy "<who,
  when>"` assigns you, unassigns them and records who approved it.
- **Switch auto memory off in one command.** Memory notes live on one machine, so nobody else on the team
  ever reads them. `adopt-dkj-repo-workflow` Part 6 adds `"autoMemoryEnabled": false` to your
  `.claude/settings.json`. Until you run it, your session start says the key is missing and names any
  memory notes already there, so you can move each one into your docs.
- **DKJ-Solutions repos are told when data sits in git.** Your session start names any folder of notes
  or data that keeps going through pull requests. Move it to OneDrive with `move-data-to-onedrive`, or
  keep it in git on purpose by listing it in `Get-GitContentAllowlist` with your reason. Content your
  CI-built site deploys from stays in git.

### Fixes you will notice

- **A drafted message is no longer sent for you.** When you ask a session to write a reply to someone,
  it gives you the text in the chat. You send it yourself.
- **Task-form release notes keep every task link.** If your store's notes list solved tasks, the
  release-notes gate now refuses a note that dropped a task link and names each missing one.
- **The live-theme branch is guarded on every route.** In a Shopify repo whose live theme deploys from a
  Git branch, opening a pull request into that branch, writing to it through `gh api`, or committing on
  it now needs the live-push marker, just as a push does. You can delete a local hook you kept for this.
- **The trunk guard no longer misreads quotes.** A commit on the trunk with a `;` or `&&` inside quotes
  is now refused like any other. You can delete a quote-aware trunk guard of your own.
- **BWJ stores keep fewer issues that wait on nothing.** A session files a GitHub issue only when a file
  in the repo will change. Work that is only an outside act goes to Asana instead, and a sweep closes
  such an issue instead of parking it. An issue whose fix lives in a colleague's project closes with a
  note saying where the fix lives.
- **BWJ Asana progress arrives as comments.** New findings on an Asana task are posted as comments, so
  colleagues get a notification. The description is written once and only corrected.
- **The release close names the notes page first.** At the end of a BWJ cut you get the release-notes
  page link before the GitHub release and the local Admin link.
- **Release blockers reach the source the same day.** The release skills now tell you to file a blocker
  the moment it happens. A blocker caused by a shared script is filed on the marketplace instead of only
  in your own repo.
