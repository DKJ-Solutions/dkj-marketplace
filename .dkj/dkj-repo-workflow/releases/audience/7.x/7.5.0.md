# Release notes v7.5.0 🚀

**Date:** 2026-11-23\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

No repo has to act on this update. Two optional settings turn on new behaviour, and they come first.
After that: release day becomes one command for Git-connected BWJ stores, docs-only pull requests ship
faster, and a round of fixes and sharper specialists.

### Optional settings

- **Put your SEO, UX or CRO owner on Asana tasks from day one.** Answer `Get-AsanaReviewFollowers` in
  `scripts/repo-config.ps1` with the Asana user ids for `seo`, `ux` and `cro`. `report-issue` then adds
  the right colleague as a follower on the mirrored Asana task when a finding touches their area, so a
  change to search, navigation, templates or checkout reaches them before it is built. Left unanswered,
  nothing changes.
- **Stop ticking the "not visible" box by hand.** Name your PR template's "nothing a visitor can see"
  box once with `Get-PrNotVisiblePattern`. When the branch document already answers the closing step as
  not visible, `open-pr` ticks that box with the reason, and the Preview check stays green.

### New

- **Go live in one command (Git-connected BWJ stores).** Once the owner has given the word,
  `go-live -Version X.Y.Z -AppDeploy` (or `-SkipAppDeploy`) runs the preflight, merges the promotion
  pull request after its checks pass, waits until the live theme matches the trunk file by file,
  deploys the app or holds it, cuts the release and updates the tasks. It stops at the first refusal
  and prints the line to resume from. Claude Code asks you to confirm before it starts, because the
  marker on that line is something a session could write itself.
- **Docs-only pull requests stop waiting on every other merge.** When `ship-pr` ships a pull request
  that touches only `.md` files, and another merge lands first, it now checks the merged result locally
  in about two minutes instead of waiting a full CI cycle of about ten.

### Fixes you will notice

- **Approved review parks resume.** A sweep returning to a branch the owner approved is no longer told
  the work belongs to another session. This holds for issues parked after the update.
- **Hotfix-lane entries stay in your release notes.** In a store that ships hotfixes through `live`, a
  cut with a live-push record no longer warns about each hotfix entry or drops it from the draft.
- **Issue bodies keep their layout.** Adding the reach label to an issue that is already filed no
  longer flattens its headings and paragraphs into one line.
- **SEO defects on live pages reach Asana.** A measured SEO defect on an indexed live page (a missing
  H1, a wrong canonical, broken structured data) now gets the reach label and lands on the store's
  Asana board and business worklist.
- **Sweeps judge every armed pull request.** The hand-off check no longer reports `[INCOMPLETE]` for a
  pull request whose required check CI has not created yet. One that never appears is reported as
  `[STUCK]`.
- **Merge-on-green no longer gives up right after a merge.** When GitHub is still computing
  mergeability, the sweep waits a minute and looks again, so the next armed pull request is not left
  for a later run.
- **Pipe a live push's output.** The live-theme guard now accepts an authorised push ending in
  `2>&1 | tail` or `> out.txt` instead of crashing, and a bad `--only` value is refused by name.
- **No line-ending diff from a reconcile on Windows.** `sync-main -ReconcileBase` now restores the
  trunk's files byte for byte, so a CRLF file no longer comes back as LF.

### Sharper specialists

- **Deliverables arrive self-checked.** The UX designer, graphic designer, long-form writer, project
  planner and data analyst check their work against a "what finished looks like" list before handing
  it back, and name anything they could not meet.
- **Visual designs follow the wireframe.** A Figma visual design is built the same way as a
  wireframe, uses the design system's one spacing and radius scale, and adapts to the wireframe where
  the two disagree.
- **Comparisons show what they weighed.** An option comparison names its criteria first, gives each
  option's main risk and long-term consequence, and ends with the criterion that decided it.
- **Your morning plan asks what to drop.** `day-plan` opens with the items that matter most and asks
  what to stop to make room.
- **Tips that improve a manual are kept.** `tip-check` now returns a concrete manual line where a tip
  sharpens how a specialist already works, and asks for all of a carousel post's slides at once.
- **Task cards no longer invent deadlines.** In a life hub, a task card's deadline and SMART answers
  come from you or a source, and stay empty otherwise.
