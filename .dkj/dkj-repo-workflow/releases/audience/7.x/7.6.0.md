# Release notes v7.6.0 🚀

**Date:** 2026-11-25\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

Most repos need do nothing. A repo running merge-on-green has one optional step and one token check,
and they come first. After that come faster CI diagnosis, clearer chat guidance, and a round of
sharper life-hub specialists.

### If you run merge-on-green

- **Stop one refused pull request from holding the queue.** The sweep now skips a pull request
  `ship-pr` refused and moves on to the next armed one. Your existing `merge-on-green.yml` is not
  rewritten. `adopt-ci-floor` prints a `[refusal]` line when your runner lacks the new step. Delete the
  file and run it again with `-Apply` to place the new one. To re-arm a refused pull request by hand,
  remove its `merge-on-green-refused` label.
- **Check your token if a green pull request is refused as "never registered".** In a private repo,
  give `FOLD_PUSH_TOKEN` read-only `Checks`, `Commit statuses`, `Actions` and `Issues`. The adopt skill
  now lists these four scopes. No runner change is needed.

### Fixes you will notice

- **A token that cannot read checks fails fast.** `ship-pr` used to wait out its whole CI budget and
  then blame the ruleset. It now stops after three failed reads, about 45 seconds, and prints `gh`'s
  own error with a pointer to the token's permissions.
- **Chris in a claude.ai or desktop chat.** The working-profile page now says what your personal
  preferences should hold: the line that loads the orchestrator skill, standing instructions and a
  short profile. Never paste the persona or manual there: that copy drifts from every release and
  loads about 10,000 words into every chat.
- **A refused repo connection is a question, not a dead end.** In a chat without a repo, Chris tries
  attaching the marketplace repo once. If that is refused, he asks you once to approve it instead of
  dropping the finding. A "report lessons upstream" line in your preferences is no longer promised to
  skip that question.

### Sharper life-hub specialists

- **One home per topic.** Ian files a dossier under the topic it is about, not the life area it
  touches, and a category follows from the path, so the two can no longer disagree.
- **Siblings are one kind.** Before placing a dossier, Ian checks it matches its siblings. A catch-all
  such as "Other" gets a proper group instead.
- **Apps live under the company.** Every app or repository you build goes under the company overview,
  and Onyx links it both ways with the subject it serves.
- **Dossiers are named for their subject.** `Tool X`, not `Replace tool X`, so the name still reads
  right once the work is done.
- **No more duplicate facts.** Before writing a fact, Ian, `inbox-sweep`, `agenda` and `ai-radar`
  check the target dossier, its parent and children, and their updates. An empty Notion title search
  no longer counts as proof the fact is new.
- **Milestones, task cards and updates connect.** A card is filed under its milestone's dossier, and
  every finished card becomes an Update there. Mail and conversations still reach a dossier without a
  card.
- **`ai-radar` places items by topic.** Each item lands on the topic page your hub's settings list,
  nested pages included, instead of a catch-all ecosystem page.
- **Corrections are not counted twice.** Fiona states per input whether a figure already contains a
  correction before applying one, and Marlowe names which figure his caveat applies to.
