# Release notes v6.17.0 🚀

**Date:** 2026-11-15\
**Type:** Minor\
**For whom:** consumers of this product

The product layer completes its core: a bottom bar, a full-screen menu and sheet, progress, status and error states, and a product page for phone and desktop.

## What changed

**No action is needed.** Update the plugins (`update-plugins`) and everything below is available. Nothing
was renamed or removed, so an app's own domain layer keeps working as it is. The new parts are
opt-in: a product uses them when it adds the class or passes the parameter.

### One product page shape

A DKJ-Solutions product page now has one layout on both screens. On a computer it is a main column with a
sidebar beside it (`.page-layout`). On a phone it is one column, with the page title shown once, in the
header. A list can be one card of compact rows (`.card--rows`) instead of a card per item. The brand book
README lays down the phone rules, and its specimens show both layouts.

### A bottom bar for phones

You can put a product's sections in the thumb zone. `.bottom-bar` in `house-product.css` is a bar fixed
to the bottom of a phone screen with four or five slots, the last always More, which opens the site menu.
With it the header drops its three-line toggle. On a wide window the bar is hidden and the menu sits in
the header. A page rendered with `Format-ProductPageHtml` gets it with `-BottomBar`.

### Full-screen menu and sheets

On a phone the menu behind the hamburger now opens full screen, like a phone's settings screen, with
Pages, Display and About sections, in place of the side drawer. Tapping the page title opens the whole
path as a bottom sheet, and a More cell opens the page's own actions as one. A product rendered with
`Format-ProductPageHtml` gets the path sheet on update; pass `-Actions` and `-SettingsHref` to fill the
rest.

### Status cards and error states

You can show where something stands and say that something failed, in the house look. `.status-card` is a
block with a kicker, a heading, the meter as its progress bar and the facts in one row. `.error-state`
turns the empty state into a failure with a red mark and a retry button.

### Sweeps get through plan-goals

Two fixes for repos that sweep a goal tree built with `plan-goal`. When a goal's current task waits for
the owner's look, or is claimed by another sweep, `issues-sweep` now takes the goal's next task instead
of reporting nothing free. Two sweeps can then work one goal at once. Each still takes one task per goal,
and its reason names the tasks it passed.

### Reviews made outside the repo

When you run `/issues-sweep-reviews` after reviewing design work in Figma, a design file or another
external page, those issues are now approved, unlabelled and closed. Before, they stayed parked under the
label the command was meant to lift.
