# Release notes v6.13.0 🚀

**Date:** 2026-11-11\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

Updating the plugins (`update-plugins`) is all most repos need to do. One item may ask you to act: if
your `scripts/repo-config.ps1` carries its own copy of `Get-TriageLabels`, read the first section.

### Stale triage labels flagged

If your repo copied `Get-TriageLabels` into `scripts/repo-config.ps1` when it adopted the workflow, and
that copy is missing a current label (for example `awaiting-decision-dev`), `check-script-contract` now
reports an `[ERROR]` at session start and in its gate. The error names the missing labels. To fix it,
replace your copy with the blueprint's text or delete the function, since the built-in set is the
default. Extra labels and your own colours and descriptions are left alone. If you never copied the
function, or kept it current, you will not notice anything.

### Sweeps respect planned goals

In a repo that plans with `plan-goal`, `issues-sweep` now offers one candidate per goal, which is its Now
task, instead of the whole tree. One consumer went from 31 free issues to 1. If Now is a step only you
can take, park it with its `awaiting-*` label so the sweep skips it.

### Planning a first goal works

`plan-goal -Apply` no longer fails with `HTTP 404` on Windows PowerShell 5.1 in a repo that has no
`goal` label yet. The label is created for you on the first run.

### Approved previews ship cleanly

If your PR template has a box for the owner's approval of a visible result, define
`Get-PrOwnerLookPattern` once (a regex for the unticked box). `open-pr` then ticks it and writes the
approval after it, and approved ships from `issues-sweep-reviews` no longer go red on a Preview check. You
no longer edit the PR body by hand. Repos without such a box notice nothing.

### Store themes, your name

For Shopify stores, answer `Get-ShopifyThemePrefix` (for example `'smartwatchbanden-'`) and your
preview and backup themes carry your store's name instead of `dkj-`. Themes already named `dkj-` are
still recognised, swept and rotated, so nothing needs cleaning up.

### Preview the release candidate

In a store whose live theme deploys from its own branch (promote-then-cut), `push-preview` now pushes
the trunk to a preview theme instead of refusing it. You can judge the release candidate with one
command before promoting, without cutting a throwaway branch first.

### Asana issues close on merge

In a BWJ store, an issue linked to an Asana task closes when its pull request lands; `notify-live` tells
the task once the release is live. If such an issue is still open within 14 days of its merge, a session
start now shows an error line naming the issue, the pull request and the two steps that end it.

### Shipped issues stay linked

A pull request opened with `open-pr -NoResolves` now carries a `Part of #<n>` line for the issue in its
branch name. `build-golive-block.ps1 -Post` finds the issue on its own, so you no longer edit the merged
PR or reach for `-Force`.

### Release notes link tasks

If you ship Asana-linked issues with `-NoResolves`, a release cut's draft note now links those tasks
too, instead of leaving them out for you to add by hand.

### Parks that clear themselves

`claim-issue -Tag -Park` refuses a reason that does not name what it waits on (an issue, a branch or
another repo, depending on the label) and shows the form to use. A park that names its blocker clears by
itself, where a blank one was skipped by every later sweep.

### Smaller things

- The release-notes page shows at most two note cards per row, so each card reads as a paragraph. Your
  page picks this up at its next `release-notes-page` run.
- A visible result's handover link is now clickable in the terminal.
- The BWJ sync log moves to `.dkj/bwj-development/SYNC-LOG.md`. The adopt step offers the move, and
  nothing breaks if you leave it.
- The brand book's "?" tooltips are easier to read, and a modal popup may carry its own h1 without the
  page shell's fit alarm firing. Apps that vendor the brand book get both with their next copy.
- `CONTRIBUTING-portable.md` now lists the labels the workflow reads or prescribes, so you know which
  `awaiting-*` labels not to rename.
