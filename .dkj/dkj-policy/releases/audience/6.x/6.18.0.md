# Release notes v6.18.0 🚀

**Date:** 2026-11-16\
**Type:** Minor\
**For whom:** consumers of this product

A weekday machine-upkeep task, a kind-label guard for BWJ issues, and merge-on-green recovering from a failed merge

## What changed

**One action, and only if your repo runs the merge-on-green runner:** re-place it with `adopt-ci-floor` to
get the recovery described below. Moving its `ref:` pin alone does not add the new job. Everything else
arrives with the plugin update (`update-plugins`), and nothing was renamed or removed.

### Armed PRs survive server errors

When GitHub answers a merge with a server error, an armed pull request now lands within about half an hour
on its own. The merge-on-green runner wakes itself again after 5, 10 and 15 minutes. Before, the PR sat
green until somebody shipped it by hand, which took over an hour twice on one day.

### Scheduled tasks, versioned

You can put the team's Claude Code Desktop scheduled tasks on every owner's machine with one command:
`place-scheduled-tasks` from the new `scheduled-tasks` skill, which also refreshes them after an update. It
ships three kinds of task:

- **BWJ release prep**, Friday 14:07, with a Monday companion: stages the store release read-only.
- **Consumer health sweep**, Monday 07:37: reports every consumer's plugin lag, CI pins, release cadence,
  unlabelled issues and red runs in one place.
- **Machine upkeep**, weekdays 07:17: updates the plugins in every checkout, fast-forwards every clean
  trunk and reports what `tidy-machine` finds, so you start the day current. It skips any checkout that is
  not clean on its trunk, and deletes, pushes and publishes nothing.

You register each task once in the Desktop app, with the schedule and folder the command prints.

### Store release day, smoother

For a Shopify store repo:

- A store at the 20-theme limit no longer deadlocks. The backup refuses with "sweep spent previews
  first", and the runbook prepared on Friday already puts that sweep first.
- `prepare-release` now tells you days ahead which paths on your push list a third party changed on live,
  and checks your Cloudflare login, where both used to surface only on the day.
- A sync that refuses on conflicts gives a first reading of each conflicted path. A sync PR no longer waits
  on a slow check the trunk does not require, and `sync-main -ReconcileBase` merges its own PR.
- The printed app deploy runs as printed, and files committed with the wrong line endings get the
  `git add --renormalize` line instead of a refusal you cannot clear.
- `notify-live` tells every task the release notes call solved, and its dry run names the tasks the token
  cannot reach, so you know who to tell by hand.
- Publishing the release-notes page takes seconds: only changed pages are uploaded.
- In a BWJ store, `gh issue create` without exactly one of `bug`, `feature` or `research` is refused
  before it runs.

### A lighter brand book

Apps on the brand book change look when they take this update, with no markup change:

- A border now marks only what you can press. Cards, notices, panels and bars stand on their fill, and
  tables stripe instead of ruling. If your own layer draws borders, they stay until you follow the rule.
- Card groups lose their grey tray. On a phone a list of card links becomes one card of rows.
- On a phone, a long fact value wraps instead of covering its label, and a wide table no longer widens
  the whole page.
- Pages over 1,500 words of reading get a warning to split them.

New, opt-in parts: a phone frame for mockups and A/B variants (`.device-stage`), a topic list for a phone
home page (`.topic-list`), and More as a page of its own (`-MoreHref`). A product menu built with
`Format-SiteHeaderHtml` now shows **Settings** with a gear where it showed **Display**.

### Sweeps and the workflow

- A decision posted as a comment now surfaces at the next sweep as a park to lift, instead of the issue
  staying skipped.
- A session opened for an issue parked under `awaiting-session-dev` is told to go ahead, not to stop.
- A `##` heading written inside a changelog entry can no longer hide the entries below it from the next
  cut.
- A work requirement that holds for every DKJ repo is now reported at the source before it is built, and
  a repo that really differs records why in its facts rule.
- Admin has an **MCP connections** page listing which connectors a session can reach, and which need a
  login.
- In a life-hub, the knowledge-base specialists read where the brain lives from their lens, so a brain
  kept outside git works.
