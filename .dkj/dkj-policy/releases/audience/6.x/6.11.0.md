# Release notes v6.11.0 🚀

**Date:** 2026-11-08\
**Type:** Minor\
**For whom:** consumers of this product

Adoption repairs for consumers, a triage-labels session check and prescribed branch prefixes

## What changed

One item may ask something of you, so start there. The rest are repairs to the move to `.dkj/dkj-policy/`
and a new session-start hint, and they need nothing beyond updating the plugins (`update-plugins`).

### Action: adopt shared branch prefixes

Every DKJ repo now uses the same branch prefixes: `feat/` gets the `feature` label, `fix/` gets `bug`,
`docs/` gets no label, and `chore/` is refused. If your `scripts/lib/branch-info.ps1` keeps prefixes of its
own (`data/`, `dossier/`, `chore/` and so on) or labels `docs/` as `documentation`, the session-start check
now shows one `[ERROR]` line naming the difference. To clear it, replace the prefix table and the
`Get-BranchInfo`, `Test-BranchName` and `Get-BranchTypes` functions with the three records in the plugin's
`blueprint/config-blueprint.json`. Fold any pending changelog entry of a type the shared table lacks first,
because only Feat, Fix, Docs and Chore remain. Release notes no longer group by a domain type. If your
table already matches, nothing changes and no line appears.

### Missing triage labels, flagged early

When your tracker lacks one of the triage labels a sweep uses, or carries one in the wrong colour, the
session start now says so in one line and names `adopt-triage-labels`, which prints every `gh label create`
you need. Before, you found out when a sweep failed to park an issue. The check creates nothing and stays
silent when the labels are complete.

### New branches work before moving

If your repo still keeps the workflow folder at the root `dkj-policy/`, `new-branch` on v6.10.0 created the
branch and then stopped before writing its document. It writes both again, without moving the folder first.

### Moving the workflow folder, repaired

Three things `adopt-workflow-folder -Apply` got wrong are fixed. If you still have the move ahead of you,
run it on this release:

- **A constitution import naming the old `dkj-claude-plugins` marketplace is rewritten.** Before, the dry
  run said `[keep]` and the repo silently loaded no constitution. The session check now warns about such a
  line until you run the move.
- **Your PR template's first-line comment names the new folder.** Before, it kept naming
  `dkj-policy/<branch>.md`. If you moved on v6.10.0, check that comment and fix it by hand; the rest of
  your template is left alone either way.
- **Comments in `scripts/repo-config.ps1` stay as written.** The move now repoints paths on code lines only
  and lists the comment lines it skipped as `[kept]`. Before, it also rewrote history comments, which then
  claimed values that were never set.

### Smaller things

- A hand-written `branch-info.ps1` can adopt `Get-BranchInfo` from the blueprint without it failing on
  first use. It no longer depends on a `Get-BranchPrefix` function the blueprint does not carry.
