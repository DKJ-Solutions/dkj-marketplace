# Release notes v6.12.0 🚀

**Date:** 2026-11-09\
**Type:** Minor\
**For whom:** consumers of this product

Safety guard on force pushes, steadier store previews, a day plan across machines and a new retro skill

## What changed

Nothing here requires action beyond updating the plugins (`update-plugins`). Two items change what a
session does on its own, so read those first: the guard against force pushes, and add-on teams that no
longer switch themselves on.

### Force pushes are refused

A session can no longer run `git push --force` (including `-f`, `--force-with-lease`, `--mirror` and a
`+` refspec) or `git reset --hard`. It is stopped and hands you the exact command to run yourself. This used
to apply only to subagents; it now covers the main session too, in every repo with `dkj-policy`, with no
setting to change. A commit message or search that merely names these commands is not stopped.

### Add-on teams start switched off

Installing `dkj-subagents-ecomm`, `dkj-subagents-lifehub` or `dkj-subagents-shopify` no longer enables it.
To use one, add `"<team>@dkj-marketplace": true` to `enabledPlugins` in your `.claude/settings.json`. A repo
that already lists the team keeps its own choice and sees no change.

### Dependencies install themselves

Installing an add-on team now brings `dkj-subagents-alpha` along, and installing `dkj-solutions` or
`bwj-development` brings `dkj-policy`. You no longer have to know to install the base plugin first.

### Store previews fill reliably

For Shopify stores, `push-preview` copes with large live themes:

- **It waits long enough.** A fresh copy of live gets 40 minutes to fill instead of 20, and keeps going
  while the copy is still growing, up to two hours. If you used to re-run `push-preview` once or twice per
  new preview, the first run now suffices.
- **Parallel previews no longer trip each other.** Several previews filling at once space out their checks,
  and a resume reuses live's file count instead of fetching it again, so one of them no longer fails on
  that count. `backup-live-theme` waits the same gentler way.

### Preview handover page

A store session hands a preview over as one Admin link: a card per market, each with a QR code you can
scan with a phone, plus the go-live block. The session runs `build-handover-page.ps1` after `push-preview`
and gives you the link. The QR codes are drawn on your machine, so preview URLs never reach an outside
service.

### Day plan across machines

The `day-plan` skill can share one plan across all your machines. Set `DKJ_DAYPLAN_REPO` to a private
repo in your user settings, and a plan made on one machine is the plan on every other; adding and closing
the day then see the whole day. Plans are only shared to a repo GitHub reports as private. Without the
setting nothing changes.

### Find what sessions search for

Type `/retro` to see which of your repo's docs recent sessions kept searching past before they could
start, and turn each real gap into an issue. It reports counts only, never transcript content, and costs
nothing until you type it.

### Parallel sweeps park cleanly

If you run several `issues-sweep` sessions at once, an issue is no longer parked two or three times with
comments that disagree. Parking now happens under the claim, in one command
(`claim-issue <n> -Tag -Park <label> -Reason "<what>"`), and a late claim on an issue that was just parked
stops instead of taking it.

### Smaller things

- Every shell call in a session is about 0.15 seconds faster, roughly 7 seconds over 50 calls.
- A specialist subagent that loops now stops at a turn limit suited to its role and returns its partial
  work, instead of running on.
- Typing `/` and a skill name now shows what to type after it, for the fifteen skills that take an
  argument.
- `claude plugin eval` runs no longer leave Admin servers and locked temp folders behind.
