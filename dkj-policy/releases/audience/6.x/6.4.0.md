# Release notes v6.4.0 🚀

**Date:** 2026-11-03\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

This release tightens two guardrails: a Shopify live push now has to come from the merged trunk, and in a
DKJ-Solutions repo a release note's headings are checked at the cut. Scaffolded workflows move to
`actions/checkout@v7`. The toolbox gets a header menu, a Settings page and a Claude page, and the brand
book gives every page more breathing room.

### Live pushes need merged work

For Shopify store repos. The live-push marker no longer authorises a push on its own: every file you push
must match `origin/main` (your trunk) byte for byte, so work that is not merged yet is refused, with each
file named and a request to merge first. The step-7 push that `live-preflight` composes from the merged
trunk passes as before, so the normal release-day flow needs no action.

A push the guard cannot read is refused too: a pattern or directory in `--only`, a shell-expanded value, a
`cd`, `--environment`, or a `SHOPIFY_FLAG_*` variable on the same line. Name the files explicitly instead.

### Checkout moves to v7

Re-adopting a CI or Shopify floor now writes `actions/checkout@v7`, so if Dependabot already moved you to
v7, a re-adopt no longer puts v5 back. One behaviour changes with it: `merge-on-green` refuses to check out
a pull request from a fork, which v7 blocks under `workflow_run`. No action needed unless you merge fork
PRs that way.

### Release note headings checked

In a repo with `dkj-solutions` enabled, the release-notes step of a cut now refuses a note whose heading
holds a code span or runs past five words, and names the line. Keep headings short and plain, and put file
names, commands and who a change is for in the text under them. These are the brand book's new rules 7 and
8, which a session building any page now follows too. A BWJ-Development repo sees no change.

### Pasteable cleanup for vanished checkouts

When `tidy-machine` finds install records for a checkout that no longer exists, it now prints the commands
that remove them, ready to paste. Run them only for a folder that is gone for good: a drive that is not
mounted, or a synced folder that is offline, looks the same.

### A menu in every header

No action needed. The house site header can carry an app's main pages between its name and the settings
button, folding into a three-line toggle on a phone, so every page of the toolbox is one click from every
other. The whole left cell of the header now goes home, not just the name, and lights up on hover.

### Settings and Claude pages

No action needed, and no link breaks:

- **Settings** is a new toolbox card with the theme picker on a page of its own, one swatch per theme and
  a light/dark toggle. It makes the same choice as the header's gear.
- **AI is now Claude**, at `/claude`, with Rules, Skills, Specialists and Performance directly under it. An
  old `/ai` link redirects.
- **Tools** in the trail now links to the toolbox root, `/`. The old `/hub` address still works.
- **A page with two titles** now shows a warning in the bottom-right alarm. A page that keeps the rule sees
  nothing new.

### More room on every page

No action needed. Brand book spacing changes reach every DKJ page that uses the house classes: blocks in a
page column stand 20px apart, menu rows and card links keep 24px between icon, label and chevron, card
grids all take the same 20px padding, and an `h2` is 20px. Card icons now sit centred in their square.
