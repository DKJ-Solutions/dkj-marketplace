# Release notes v6.8.0 🚀

**Date:** 2026-11-05\
**Type:** Minor\
**For whom:** consumers of this product

The Toolbox becomes Admin, the sweep skills share one name, and parked results ship in one pass

## What changed

Two items ask something of you. Act on those first. The rest needs no action: update the plugins and your
next session picks them up.

### Action: the sweep commands have new names

You now type `/issues-sweep` instead of `/sweep-issues`, and `/issues-sweep-decisions` instead of
`/sweep-decisions`. The old commands are gone: typing one finds no skill. Sweeps you recorded under the old
names still show in the logbook.

### Action if your own code styles against the Toolbox: it is now Admin

You now open **Admin** where you used to open the Toolbox, and the session-start line says `Admin:`. The
navigation is a flat list under section headings: **Home**, **Product** (your storefront), **Development**
(GitHub, Release notes, Claude, Installed plugins) and **Settings** at the foot. Every development page
moved under `/dev/...`, and every old address still takes you to the same page, so your bookmarks keep
working. No action is needed unless your own code passes `-BrandTag 'toolbox'` or uses the `.tree*` classes.
In that case, switch to `-BrandTag 'admin'` and the `.nav-*` classes. `'toolbox'` still works in this
release, as a stopgap.

### Ship every parked result in one command

You can now approve and ship every issue waiting on your review (`awaiting-review-dev`) in one pass with
`/issues-sweep-reviews`, instead of shipping each parked branch by hand. Only you can start it, because
typing the command is your permission to merge. Your clients' reviews (`awaiting-review-client`) are never
touched. Any issue it cannot ship safely stays parked, and the sweep tells you why.

### Every parked result names where to look

When a session stops for your look, its report now gives the exact URL of each changed page on a line of its
own, so you open it instead of hunting for it.

### Clearer brand-book rules for management screens

When you build a management screen in Admin's desktop shell, the brand book now tells you which rules you
can leave out (the breadcrumb bar, the cards, the 44px target) and which still hold. A sortable column header
in a dense table no longer catches clicks meant for the row below it.
