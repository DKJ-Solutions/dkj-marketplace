# Release notes v6.3.0 🚀

**Date:** 2026-11-02\
**Type:** Minor\
**For whom:** consumers of this product

## What changed

### Taking the new brand book copy? Drop the prose class

`.prose` is retired. Remove the class from your rendered markdown: plain headings, `code`, `pre`, lists,
quotes and rules now take the house look by themselves, with headings at the same sizes as everywhere else.
Your own classes still win, because the new base rules have zero specificity.

Two things to do by hand:

- **Set the space between blocks in your own layout.** `.prose` used to supply it.
- **Rename `--prose-h1` … `--prose-h3`** if your layer reads them. They are retired tokens, so the
  brand book check names each leftover use.

A table renders as a `.table` inside a `.table-wrap`. The README section "`.prose` retired, November 2,
2026" has the full move.

### …and drop the mark from your site header

The site header now carries the name alone. If your app has its own header, remove the
`.site-header__mark` span: it has no rule any more, so a leftover just shows unstyled initials. Size the
header name with the new `--text-title` token (20px), which you can tune without moving every `h2`.

### The brand book check now flags typed and mixed colours

If your repo runs the brand book gate, expect a new `colour` finding for every rule that types a colour
(`#hex`, `rgb()`, `hsl()`) or derives one (`color-mix()`, `oklch()`, `rgb(from …)`). It arrives at your next
CI run, not at your next update, because the reusable workflow tracks `main`. A repo that was green only
turns red if it has such a rule. The three DKJ-Solutions repos measured already failed on retired token
names.

To fix one, add a domain token that holds the colour (`--my-row-tint: …`) and read it with `var()`, or
allowlist a false positive in `Get-HouseStyleAllowlist` with its reason. The README now says the same
thing. It used to suggest a `color-mix()` inside a token's own value was allowed, and it is not.

### Shopify stores: a slow live theme no longer breaks release-day preflight

No action needed, but three new options help if your live theme copies slowly:

- **The backup waits as long as the copy keeps growing.** Past its timeout it carries on while the file
  count rises, and stops on a stall or at three times the wait.
- **`live-preflight -BackupTimeoutMinutes 45`** sets a longer wait in one run, without a manual backup
  followed by `-SkipBackup`.
- **`live-preflight -BackupVerifyExisting <id>`** retries a timed-out backup by verifying the copy that run
  left behind, instead of duplicating live again. Use the id the timed-out run printed. Measured in a
  consumer, each retry without it cost an extra theme slot.

### Promote-then-cut stores: the LIVE marker moves by itself

No action needed. If you push to live and then cut, the cut now moves the `**LIVE**` marker in your release
history onto the new row. Your release-notes page names the version that is actually live, with no manual
edit after each release.

### Your toolbox looks a little different

No action needed, and no link breaks:

- The home page cards stand on the page instead of inside a grey panel.
- **Performance** is now under **AI**, and the **Test gate** is under **GitHub**. Every route is unchanged.
- A specialist's lens page shows formatted text instead of raw markdown.
- The session-start line reads *"the brand book holds at vX.Y.Z"*, the same name the docs use.
